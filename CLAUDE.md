# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Claude Code **plugin marketplace** — not application code. It hosts plugins that users install via `/plugin marketplace add grahambrooks/agent-skills`. The repo was bootstrapped from [stbenjam/claude-marketplace-template](https://github.com/stbenjam/claude-marketplace-template) and retains the template's update mechanism (`make update-from-template`).

## Common commands

| Command | Purpose |
|---|---|
| `make lint` | Run claudelint in strict mode via container (podman preferred, falls back to docker). Must pass — CI runs this on every push/PR. |
| `make update` | Regenerate `PLUGINS.md` and `docs/data.json` from plugin metadata. **Run after any change under `plugins/`** or `make lint` will fail. |
| `make new-plugin NAME=foo` | Scaffold a new plugin with starter `plugin.json` / `commands/example.md` / `README.md` and register it in `.claude-plugin/marketplace.json`. |
| `make update-from-template` | Pull latest `docs/index.html` and build scripts from the upstream template repo, then re-apply branding from `.template-config.json`. Overwrites those files — never hand-edit them. |

There is no separate test suite. Validation is `make lint`.

## Architecture

### Marketplace registry

`.claude-plugin/marketplace.json` is the source of truth for which plugins exist. Every directory under `plugins/` referenced here must contain a `.claude-plugin/plugin.json`. `make new-plugin` patches this file automatically; manual additions need the same `{name, source, description}` shape.

### Plugin layout

Each plugin in `plugins/<name>/` may contain:

- `.claude-plugin/plugin.json` — required metadata (name, description, version, author)
- `commands/*.md` — slash commands, exposed as `/<plugin-name>:<command-stem>`. Frontmatter: `description`, `argument-hint`.
- `skills/<skill-id>/SKILL.md` — task-specific skills. Frontmatter: `name`, `description`.
- `hooks/*.md` — event hooks. Frontmatter: `event`, `description`.
- `agents/*.md` — subagent definitions. Frontmatter: `name`, `description`, `subagent_type`.
- `.mcp.json` — optional MCP server config. Uses `${CLAUDE_PLUGIN_ROOT}` to reference plugin-local paths.
- `README.md` — surfaced in generated docs.

`plugins/code-intelligence/` is the live reference and exercises four of those surfaces (plugin.json, skill, hook, `.mcp.json`).

### Generated artifacts (do not hand-edit)

- `PLUGINS.md` — generated by `scripts/generate_plugin_docs.py` from each plugin's `plugin.json` + `commands/*.md` frontmatter.
- `docs/data.json` — generated by `scripts/build-website.py`. Feeds the GitHub Pages site at `docs/index.html`. Aggregates commands, skills, hooks, agents, and `.mcp.json` presence per plugin.
- `docs/index.html` — pulled from upstream template by `make update-from-template`; branded via `scripts/apply-branding.py` using `.template-config.json`.

Both `PLUGINS.md` and `docs/data.json` are checked by the custom claudelint rule in `.claudelint-custom.py` (`plugins-doc-up-to-date`) — it re-runs the generators and fails if output differs from what's committed. Always commit the regenerated files alongside plugin changes.

### Branding pipeline

`.template-config.json` holds marketplace name, owner, GitHub repo, and color scheme. `scripts/apply-branding.py` substitutes `{{PLACEHOLDER}}` tokens (see `TEMPLATE.md` for the full list) into `docs/index.html`, `.claude-plugin/marketplace.json`, the example plugin's `plugin.json`, and `README.md`. Re-runs after `make update-from-template`.
